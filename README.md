# wheel_speed_monitor

RC 攀爬车四轮转速监测验证台（v1）。

A3144 霍尔传感器 + 小铷磁铁随车轮转动触发脉冲，ESP32-S3 用 PCNT 硬件计数，
经 WebSocket 推送遥测帧到内嵌网页验证台。采集器框架可扩展（后续加 IMU 姿态等）。

## 硬件与接线

板卡：Freenove ESP32-S3 WROOM CAM（FNK0085），板载 DVP 摄像头与 8MB PSRAM。

| 轮 | 霍尔 GPIO | 说明 |
|---|---|---|
| 左前 | GPIO1 | |
| 右前 | GPIO14 | 闪光灯焊盘可选接口，不用 |
| 左后 | GPIO21 | |
| 右后 | GPIO47 | |

A3144 接线：VCC ← ESP32 3.3V（**注意：数据手册标称 4.5–24V，3.3V 低于规格下限，
可能工作但不保证**）、GND ← GND、OUT → GPIO 并 10kΩ 上拉到 3.3V（面板已加）。
磁铁南极靠近 → OUT 拉低（下降沿 = 一次触发）。

### 3.3V 供电排查预案

1. 打开验证台「原始 IO 电平监视」：
   - 静止时 4 路全"高" = 上拉有效；某路非高 → 查该路接线/上拉电阻。
   - 磁铁靠近时对应 GPIO 闪"低" = 触发正常。
2. 静止高、磁铁靠近不闪低 → 万用表量 A3144 VCC 对 GND 电压：
   - 不足 3.1V 且无动作 → **改 5V 供电**：VCC 改接 ESP32 5V 引脚；
     **输出上拉保持接 3.3V**（A3144 是开集电极，上拉电压决定 GPIO 高电平，安全）。
3. 翻转但 RPM 乱跳 → 磁铁南极面朝向传感器、间距 < 5mm；网页「去抖」填 20 开软件去抖。

## 差速舵机

前、后差速各接一个标准角度舵机（50Hz，脉宽 500–2500µs，1500µs 中位）。
信号线接 **GPIO41（前差速）** 和 **GPIO42（后差速）**。

自动模式下每个通道只有两个落点，各自可配：**解锁档**是正常行驶位置，
**锁定档**是差速锁死位置。差速器只有锁止和释放两个确定位置，中间行程没有意义，
所以不做连续的角度映射。前后轴分别配置——两轴舵机的安装朝向或连杆行程不同时，
各填各的行程端即可（比如后轴装反，就把它的锁定档填到另一端），不需要「反向」开关。

这两个脚在 ESP32-S3 上是 JTAG 引脚，但默认的调试通道是芯片内置的
USB-Serial-JTAG，它走芯片内部的 TAP 控制器，不占用这四个引脚，所以照用不误：
不用关 JTAG，不用改 console，烧录和 monitor 的用法一个字都不变。唯一会撞的
情况是有人烧了 `DIS_USB_JTAG` efuse 把 JTAG 引到引脚上。

舵机电源必须独立 5V 并与 ESP32 共地。堵转电流可能超过 1A，不要从板子的
3.3V 取电。

### 在验证台上验证（不接真舵机）

设置 tab 里勾上「模拟舵机模型」，执行器就换成软件模型：它按设定速率朝目标
脉宽移动，把"指令到哪、现在到哪、到没到"如实回传页面。轮速照旧用模拟模式喂，
整条判定链跟接了真舵机时走的是同一份代码。

能在验证台上复现的几件事：

| 想看的现象 | 怎么设 |
|---|---|
| 锁定差速 | 模拟转速设成左前 200、其余 60。前轴速差比例 0.7，超过 0.30 的门槛，前差速跳到锁定档 |
| 锁上后不被轮速带跑 | 锁定期间把左前改回 60，前差速继续锁着，不会马上松 |
| 试探与退避 | 保持时长（默认 3 秒）走完，状态变「试探中」、脉宽回解锁档。这时再制造打滑会立刻锁回，保持时长翻倍到 6 秒，再往后 12 秒，封顶 30 秒 |
| 退避复位 | 四个轮子都设成 60，或者全部停到 0。试探窗口走完就回到「已解锁」，保持时长复位成 3 秒 |

页面上的阶段徽章（已解锁 / 锁定中 / 试探中）和三段式状态机是一一对应的，
锁定保持时长的翻倍也在卡片上直接显示。

### 接真舵机

设置 tab 里取消勾选「模拟舵机模型」，执行器切成 LEDC 输出。轮速仍然可以用
模拟模式喂，这正是"用验证台的模拟轮速驱动真舵机"的用法。

拿示波器或逻辑分析仪量 GPIO41/42：应当是 50Hz 方波，脉宽等于页面显示的指令
值。通道关掉时引脚停在低电平、没有脉冲，舵机脱力。真实舵机的行程时间比模拟
模型慢，如果试探窗口（默认 2000ms）不够它走完，在设置页调大即可。

## 遥控输入（差速锁模式切换）

接收机三路 PWM 接 **GPIO38（模式通道）/ GPIO39（前差速）/ GPIO40（后差速）**，
50Hz、脉宽 500–2500µs，与舵机同一量程。这三根脚原本是板载 microSD 卡座：本项目
不用 SD，卡座让位；39/40 兼外部 JTAG 脚，与已在用的 41/42 是同一情况。

模式通道决定差速锁听谁。**≥1500µs 判手动**：前后差速通道的脉宽原样透传给舵机，
遥控给多少就输出多少；**<1500µs 判自动**：忽略遥控，仍按轮速走打滑状态机。

任一路超过 100ms 没收到脉冲即判丢信号（约 5 帧），**那一路单独回落设置页配置**：
模式通道掉了就按设置页的自动/手动，差速通道掉了就按该轴的手动目标滑杆。两路判定
互相独立，一根线松掉不连累另一根——车上最常见的故障就是信号线松脱。

### 在验证台上验证（不接接收机）

设置 tab 的「遥控模拟」卡：勾上开关等于接了一台一直在发脉冲的接收机，三个滑杆
就是三路通道的脉宽（步进 10，能精确停在 1490 与 1500）。监测 tab 的「遥控输入」
卡如实显示三路的值、是否有效、以及每根轴此刻吃的是透传值还是滑杆值。

| 想看的现象 | 怎么设 |
|---|---|
| 模式切换 | 打开模拟，模式通道滑到 1490 再滑到 1500，生效模式在自动/手动之间翻 |
| 手动透传 | 模式通道 1700（手动），前差速 1200 → 前轴指令 1200µs，后轴不受影响 |
| 自动忽略遥控 | 模式通道 1200（自动），拨动两根差速通道滑杆，两轴指令不跟着动 |
| 掉线回落 | 关掉模拟开关（等价接收机断电），三路变「无信号（N ms 前）」，模式与目标回落设置页配置 |

### 接真接收机

设置 tab 里把「遥控模拟」关掉（开着会把 GPIO38/39/40 上的真实信号盖掉），接收机
三根信号线接到 38/39/40，供电与 ESP32 共地。启动日志里应出现
`rccap: RC 捕获就绪 模式=GPIO38 前=39 后=40`。

接线前先确认接收机的 failsafe 行为：部分接收机失联时会输出预设值（比如固定
1500µs），从我们的超时判据看那是"信号一直有效"。这属于接收机侧配置，页面上的
通道值看得见。

## 画面回传（摄像头预览）

板载 DVP 摄像头（OV2640/OV5640，驱动按 PID 自动识别）通过 MJPEG over HTTP
回传，浏览器 `<img>` 直接播放。叠加信息（轮速/舵机/遥控/系统）在浏览器里用
canvas 绘制，不烧进 JPEG，所以不额外吃 ESP32 的 CPU。

摄像头引脚：SCCB 4/5、VSYNC 6、HREF 7、PCLK 13、XCLK 15、
Y2..Y9 = 11/9/8/10/12/18/17/16；GPIO14 是霍尔，不属于摄像头。
摄像头和 PSRAM 需要 `sdkconfig.defaults` 里的 `CONFIG_SPIRAM*` 与
`CONFIG_CAMERA_CORE1`，少了 PSRAM 相机会初始化失败。

**什么时候开始采集**：默认策略「按需」——只有监测 tab 的预览流请求才启动相机。
手机连上热点、停在设置页都不采集。切到设置 tab 后流和采集保持 30 秒，
30 秒内切回不断流、不重新初始化；超过 30 秒才断流停采。页面关闭或流意外断开
走 30 秒宽限。设置页还可以选「常开」（调试，发热/功耗自己担）或「关闭」。

**帧率**：设置页的帧率上限同时约束传感器采集和 MJPEG 发送。相机初始化后会
实测一次基准帧率，OV2640 通过调 CLKRC、OV5640 通过拉长 VTS 把采集降到目标值，
配置低帧率时不会仍然全速空转发热。推流过程中，服务端还会根据发送阻塞时间
自动降速（最低 5fps），网络恢复后逐步升回配置上限；页面的“自动降速”标注和
`sys.cam.fps_eff` 能直接看到当前值。

| 想看的现象 | 怎么设 |
|---|---|
| 按需启动 | 停在设置 tab，串口没有相机 init 日志；切到监测 tab 后出现 init 日志并出画面 |
| 切 tab 保持 | 切到设置 tab，页面状态显示「预览暂停，N 秒后停止」，30 秒内切回画面不中断 |
| 30 秒超时 | 切走超过 30 秒，服务端断流并 deinit；切回时重新 init |
| 静态帧兜底 | 勾「静态帧模式」，弱网下用 1 秒一次的快照代替 MJPEG，叠加层照常刷新 |
| 采集侧降帧 | 把帧率上限从 15 改到 5，串口出现 `sensor fps calibrated`，`sys.cam.fps` 降到约 5；模组温度应低于 15fps 时 |
| 网络自动降速 | 用限速/弱网环境推流，串口出现 `network throttle`，页面标注“自动降速”；网络恢复后逐步回到上限 |
| 全屏查看 | 点「全屏」进入浏览器全屏，视频和叠加层一起铺满；按 Esc 或右上角「退出全屏」退出。不支持元素全屏的浏览器会退化为铺满视口 |
| 原始快照 | 点「原始快照 ⤓」下载当前 JPEG；相机按需待机时页面会自动等它启动 |
| 画面翻转 | 装车方向不对时勾「画面翻转」，只翻视频，叠加层保持正向 |

## 构建与烧录

```bash
# 环境加载（每次新终端）
get_idf

# 首次（会联网拉 espressif/esp32-camera 到 managed_components/）
idf.py set-target esp32s3
idf.py build

# 烧录（端口先 ls /dev/cu.*）
idf.py -p /dev/cu.usbmodemXXX flash monitor
```

## 使用

1. 烧录后手机/电脑连 WiFi 热点 `wheel-bench`（开放，无密码）。
2. 浏览器打开 `http://192.168.4.1`。
3. 页面分两个 tab：
   - **监测**：4 轮 RPM/线速度/频率/累计脉冲、画面回传（MJPEG + 叠加层）、
     轮速曲线、原始 IO 电平监视、差速舵机状态卡、遥控输入卡。
   - **设置**：采集配置（磁铁数/轮径/EMA/去抖/每轮启用）、模拟模式转速、
     差速舵机的全部参数、遥控模拟（三路注入脉宽）、画面回传配置
     （策略/分辨率/画质/采集发送帧率上限/叠加项）。
4. 配置自动持久化到 NVS。「模拟模式」用合成数据跑完显示与计算链路，
   走的是和真实霍尔完全相同的那条数据链。

```
main/           入口、配置、Web 服务、内嵌验证台页、相机生命周期/流任务

  wheel_sensor/ PCNT 硬件薄封装（A3144 4 路）
  strategy/     差速状态机（打滑判定/锁定保持/试探退避/脉宽映射）+ JSON 渲染

  servo_drv/    LEDC 硬件输出（IDF 依赖）
```

## 扩展：新增采集器（如 IMU）

1. `telemetry.h` 的 `telem_type_t` 末尾加枚举值；
2. 实现 `telem_collector_ops_t`（init/sample/render/reset_baseline）；
3. `app_main` 里 `telem_register` 注册；
4. 前端 `applyFrame` 的 collectors 遍历加一个渲染函数。

协议约定：`sample` 每采样窗口调用一次（50ms），计算量须小；`render` 输出本类型
JSON 对象（不含外层包裹），字段名即前端协议，变更需前后端同步。
